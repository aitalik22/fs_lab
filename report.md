## Задание 2. Исследование файловой системы

### Гипотеза

1. Корневая файловая система необязательно находится на /dev/sda1. Она может располагаться на другом устройстве.
2. В Linux может быть несколько одновременно смонтированных файловых систем.
3. Каталог /proc не является обычным дисковым каталогом, поскольку содержит виртуальную информацию о процессах и ядре операционной системы.

### Эксперимент

Для исследования файловой системы были выполнены команды:

- `ls /` — просмотр корневого каталога.
- `lsblk -f` — исследование блочных устройств.
- `df -hT -x squashfs` — проверка свободного пространства.
- `findmnt /` — определение источника корневой файловой системы.
- `findmnt /proc` — исследование виртуальной файловой системы proc.
- `findmnt /sys` — исследование файловой системы sysfs.

Результаты исследования дисков сохранены в файл `disks.txt`.

### Наблюдение

В ходе исследования были получены следующие результаты:

- Корневое устройство: /dev/sdd.
- Тип файловой системы: ext4.
- Точка монтирования: /.
- Общий объём: 1007 ГиБ.
- Занятое пространство: 2,6 ГиБ.
- Доступное пространство: 954 ГиБ.
- Использование пространства по данным df: 1%.

Также обнаружены файловые системы tmpfs, overlay, 9p и область подкачки swap.

### Вывод

В результате исследования установлено, что корневая файловая система Ubuntu расположена на устройстве /dev/sdd и имеет тип ext4. Внутри виртуальной файловой системы доступно 954 ГиБ, поэтому нехватки места по её показателям не наблюдается.

Linux позволяет одновременно использовать несколько файловых систем. Каталог /proc не является обычным дисковым каталогом, так как предоставляет информацию о процессах и ядре операционной системы.

Первоначальная гипотеза подтвердилась.


## Задание 3. Исследование inode и размера файла

### Гипотеза

Предполагаю, что при переименовании файла в пределах одной файловой системы:

- Номер inode не изменится.
- Содержимое файла останется прежним.
- Блоки данных не будут скопированы.
- Изменится только имя файла в записи каталога.

### Эксперимент
Для исследования были выполнены следующие команды:

```bash
echo "Hello" > report.txt
stat report.txt
ls -li report.txt
mv report.txt final.txt
stat final.txt
ls -li final.txt
ls -l final.txt
du -h final.txt
touch empty.txt
stat empty.txt
du -h empty.txt
stat final.txt > inode_info.txt
```

### Наблюдение

После переименования файла report.txt в final.txt номер inode остался прежним — 20980. Содержимое файла не изменилось.

Результаты исследования размеров файлов:

| Характеристика | final.txt | empty.txt |
|---|---|---|
| Inode | 20980 | 21481 |
| Логический размер | 6 байт | 0 байт |
| Blocks | 8 | 0 |
| Выделенное пространство | 4096 байт | 0 байт |
| Количество ссылок | 1 | 1 |
| Права доступа | 0644 | 0644 |

Файл final.txt содержит слово Hello и символ переноса строки, поэтому его логический размер составляет 6 байт.

Файловая система выделила 8 единиц по 512 байт:

8 × 512 = 4096 байт.

Пустой файл empty.txt имеет собственный inode, но не содержит данных, поэтому блоки данных ему не выделены.

### Ответы на вопросы

1. Почему переименование в пределах одной файловой системы обычно не меняет inode?

При переименовании изменяется имя файла в записи каталога. Сам inode и блоки данных остаются прежними.

2. Где хранится имя файла?

Имя файла хранится в записи каталога, которая связывает его с номером inode.

3. Почему Size и Blocks измеряют разные характеристики?

Size показывает фактический логический размер содержимого файла в байтах, а Blocks показывает количество выделенных единиц дискового пространства по 512 байт.

### Вывод

В ходе эксперимента установлено, что переименование файла не приводит к созданию нового inode или копированию данных в пределах одной файловой системы. Также было обнаружено, что логический размер файла может отличаться от выделенного дискового пространства. Пустой файл имеет метаданные, но не занимает блоки данных.

Гипотеза подтвердилась.
